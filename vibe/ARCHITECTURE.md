
## Folder Structure Rules

- Root HTML files are public routes for GitHub Pages: `index.html`, `404.html`, and legal pages.
- `scss/` is intended source for main portfolio styling. `css/style.css` is the compiled production stylesheet.
- `css/legal-pages.css` is standalone CSS for legal pages and is not generated from `scss/style.scss`.
- `js/custom.js` is the editable behavior source; `js/custom.min.js` is generated by Terser.
- `js/site.js` contains small vanilla browser utilities such as service worker registration and current year injection.
- `js/vendor/` contains third-party browser libraries; do not edit manually.
- `images/`, `fonts/`, and `cv/` are static public assets referenced by root HTML.
- `portofolio/web/*` contains independent static demo sites and should be treated as embedded portfolio artifacts unless explicitly scoped.

## Naming Conventions

- Root pages use kebab-case or descriptive lowercase filenames: `privacy-policy.html`, `terms-and-conditions.html`.
- CSS classes are mostly kebab-case and BEM-like for newer sections: `adblock-alert__content`, `legal-brand__mark`.
- JavaScript uses IIFE modules and camelCase function names: `initServiceWorker`, `portfolioMasonry`, `initListToggle`.
- HTML section IDs follow `section-*`, but there is existing drift between navbar links and actual section IDs.

## Known Architectural Risks

- `server.js` serves `public/`, but no `public/` directory exists. `npm start` is likely misaligned with the current root static layout.
- Navbar links target `#section-work-experience` and `#section-organization`, but observed section IDs are `#section-resume` and `#section-oe`.
- `npm run build` succeeds after `npm install`, but Sass emits deprecation warnings and regenerating `css/style.css` removes styles that exist only in compiled CSS.
- `npm test` is a placeholder that exits with failure.
- Service worker registers `/sw.js`, which is correct for user-site root GitHub Pages but would need adjustment if hosted under a subpath.
